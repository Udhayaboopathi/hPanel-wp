Migrate a WordPress Website

One-upload import (WPvivid & standard backups)

Two ways in: (1) upload the site's wp-content as one ZIP (if it also contains the WPvivid database file — the …-db file — the database is taken from there), or (2) if your backup is a WPvivid multi-part set (the separate …-plugins.zip, …-themes.zip, …-uploads.zip, …-mu-plugins.zip, …-others.zip and …-db.gz files), select all of them at once in the file field — KR Host combines them itself. A database export (.sql, .sql.gz, or a ZIP of one) can also be added as the second file. KR Host then deploys the site as a tracked job: it provisions the container and a fresh database, installs your files, and imports the database unchanged — the site's original admin accounts come across in it. Leave the domain empty to keep the site's original domain (read from the database; afterwards you only point that domain's DNS at this server), or enter a new domain and every internal URL is rewritten to it. Leave all three administrator fields empty to keep the backup's original WordPress admin — or fill all three to add/reset an administrator account during the import.

Notes: the source table prefix and old domain are detected from the dump automatically. Source-server extras (LiteSpeed cache folders, WPvivid staging folders) are skipped. The old wp-config.php is never imported — KR Host supplies the database credentials itself. Sites that ran on LiteSpeed keep working, but the LiteSpeed Cache plugin's server-level caching does not apply on this Apache stack; remove that plugin after the move.

Prefer to migrate by hand?

The same result is reachable step by step with the panel's existing tools:

Step 1 — Create the new website

Create an empty WordPress site on the target domain with the Create Website wizard and let provisioning finish. This gives the migrated site its own container, database and restricted database user.

Step 2 — Bring the files over

Upload the old site's wp-content (uploads, themes, plugins) into the new site with the File Manager. For a site that already exists in KR Host, pick it here:

Step 3 — Import the database

Connect to the new site's database with your database tool (the external endpoint is shown on the site's Database page) and import the old dump there, or simply use the one-upload import above, which does this for you. If the domain changed, use the site's Domains & SSL page → Change domain afterwards — it rewrites the site's internal URLs to the new domain for you — and flush permalinks once.

Step 4 — Verify, then point DNS

Open the site, check pages, forms and media, then point the domain's DNS A records at this server (the exact records are shown on the site's Domains & SSL page). Keep the old hosting live until DNS has propagated.

Moving between KR Host servers?

Take a backup on the source server, download it, and use the one-upload import here with the backup's files and database — or follow the manual steps above. Restoring a backup archive directly into a different site is still not supported; backups restore into the site that created them.
